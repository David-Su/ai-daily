## Why

送进 LLM 评分与汇总的抓取正文里混入了大量与语义无关的噪音：Markdown 图片（平均每条约 2.6 张）、站点注释与广告残留、导购链接、多余空行。这些内容不影响人类阅读，却按字符计入 token。单日图片噪音约 3 万 token 起，评分阶段每天重复支付 12 次，Digest 阶段再支付一次。现在是动刀成本最低、质量风险最小的一项优化。

## What Changes

- 在抓取内容转 Markdown 之后、送 LLM 之前，增加一道输入清洗：移除图片标记、广告/推广残留、导购链接，压缩多余空行。
- 清洗同时作用于评分输入与推送（Digest / 即时）输入，存盘的原始内容保持不变。
- 清洗只删除可判定为噪音的成分，不改写、不概括、不重排正文语义。

## Capabilities

### New Capabilities

- `input-cleaning`: 送 LLM 前的输入清洗能力，定义哪些成分属于噪音、清洗的作用范围与不变性保证。

### Modified Capabilities

（无）

## Impact

- 受影响的代码：`src/processor.py`（清洗位置）、`src/llm.py`（评分与推送的输入构造）、`src/main.py`（抓取流水线调用点）。
- 对外行为：LLM 输入变短，输出内容质量预期不变；存盘文件与推送格式不变。
- 依赖与配置：不新增依赖，不改配置项；`docs/tech-spec.md` 中与内容处理相关的描述需同步。
