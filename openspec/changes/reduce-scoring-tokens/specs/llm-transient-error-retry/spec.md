## Purpose

让 LLM 请求的超时和网络异常与可重试的 HTTP 状态码一样按临时故障重试并走兜底，并在失败日志中写明异常类型，避免评分批次静默失败、白白浪费已发送的输入 token。

## ADDED Requirements

### Requirement: 超时与网络异常按临时故障重试

主模型请求发生超时或网络连接异常时，系统 MUST 与可重试的 HTTP 状态码采用相同的策略：在同一主模型上按 `llm.max_retries` 的总尝试次数退避重试，重试期间模型名保持不变。主模型的尝试全部失败后，若已声明 `llm.fallback` 且本次调用允许兜底，系统 SHALL 改用兜底端点再请求恰好一次。兜底请求发生超时或网络异常时，系统 MUST 报告本次调用失败，SHALL NOT 对兜底端点重试。

不可重试的 HTTP 状态码（例如 `401`、`404`）的处理方式保持不变。

#### Scenario: 超时后重试成功
- **WHEN** 主模型第一次请求超时，第二次请求返回 HTTP 200
- **THEN** 系统返回第二次请求的正文，不请求兜底端点

#### Scenario: 主模型持续超时后走兜底
- **WHEN** 主模型在 `max_retries` 次尝试中每次都超时或网络异常，且已声明兜底端点
- **THEN** 系统对兜底端点请求恰好一次，并在成功时返回其正文

#### Scenario: 兜底请求也超时
- **WHEN** 主模型的尝试全部因超时失败，兜底请求也超时
- **THEN** 本次调用失败，抛出的异常是兜底请求的超时异常，兜底端点只被请求一次

#### Scenario: 未声明兜底
- **WHEN** 主模型的尝试全部因网络异常失败，且未声明兜底端点
- **THEN** 本次调用失败，抛出最后一次尝试的网络异常

#### Scenario: 不可重试状态码行为不变
- **WHEN** 主模型返回 HTTP 404
- **THEN** 系统不对主模型重试，按原有规则直接走兜底或报告失败

### Requirement: 重试日志区分状态码与异常

主模型进入重试时，系统 MUST 输出一条重试日志。由 HTTP 状态码触发的重试沿用原有格式；由超时或网络异常触发的重试，日志 MUST 包含异常类型名和当前重试序号。

#### Scenario: 超时触发重试
- **WHEN** 主模型第一次请求超时并进入重试
- **THEN** 日志中出现一条重试记录，包含 `TimeoutError` 和重试序号

### Requirement: 失败日志包含异常类型

评分批次失败、即时快讯生成失败和汇总生成失败时，日志 MUST 包含异常类型名，后跟异常消息。异常消息为空时，日志 MUST 仍然包含异常类型名。异常通知中的错误文本 MUST 与日志中的错误文本一致。

#### Scenario: 超时导致评分批次失败
- **WHEN** 某评分批次的调用因超时最终失败，异常消息为空
- **THEN** 该批次的失败日志包含 `TimeoutError`，冒号后不再只剩空白

#### Scenario: 评分结果解析失败
- **WHEN** 某评分批次返回的正文无法解析为评分 JSON
- **THEN** 失败日志以 `ValueError` 开头，后跟原有的解析错误消息

#### Scenario: 汇总生成失败
- **WHEN** 某 domain 的汇总调用最终失败
- **THEN** 汇总失败日志和发送的异常通知都包含异常类型名
