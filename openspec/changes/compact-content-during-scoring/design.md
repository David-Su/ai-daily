## Context

参见 `proposal.md` 的 Why。当前评分请求和批次估算在两处都使用 `content[:2000]`，而评分结果合并后由 digest 与即时推送继续读取同一个 `content` 字段。评分调用已经使用结构化 JSON 响应，且条目通过整数 `id` 与原始输入合并；下游没有独立的压缩正文字段。

本设计必须同时满足三个约束：评分请求能看到完整正文；分类、评分与压缩在提示词中是独立任务；下游仍只读取 `content`。配置模型禁止未知字段，因此新增阈值必须同步配置、文档和测试。正文被压缩后还会影响现有按正文建立的跨日去重指纹，需要显式处理。

## Goals / Non-Goals

**Goals:**

- 在一次评分 LLM 调用中，为达到分数门槛且超过长度阈值的条目生成高保真压缩正文。
- 以完整原文作为分类、评分和压缩的共同事实输入，避免固定字符截断。
- 让有效的更短正文覆盖原 `content`，使现有 digest、即时推送和存储调用链无需认识新字段。
- 对实际节省的字符数和百分比提供逐条可观察日志，并对异常结果安全回退。
- 保持批次拆分、跨批次 id 合并和历史数据读取的可验证性。

**Non-Goals:**

- 不新增独立的 `compressed_content`、压缩状态或下游分支字段。
- 不把 `summary` 当作正文替代品，也不让评分、标签或领域判断改写事实内容。
- 不在本次变更中引入第二个专门的压缩 LLM 调用、自动升档或动态成本预算。
- 不改变 digest/即时推送的提示词业务规则和输出格式。
- 不承诺压缩结果在语义上绝对等价；通过提示词约束、长度校验、回退和样本回归降低风险。

## Decisions

### 1. 在同一评分响应中完成三项独立任务

评分 prompt 分为“分类”“评分/标签/摘要”“高保真正文压缩”三个明确章节。模型可以先完成分类和评分，再用分数决定是否输出 `content`，但压缩正文只能引用原始 `title` 与完整 `content`，不得引用模型生成的 `summary`、`tags`、`domain` 或评分理由。

响应中的 item 至少包含 `id`、`domain`、`score`、`tags`、`summary`；只有 `score >= lowest_retained_score` 且原文长度超过阈值时才允许包含 `content`。为避免让模型自行数 Unicode 字符，输入条目增加仅供本次 prompt 使用的 `needs_content_compaction` 布尔值；程序根据配置阈值计算它，不持久化。程序端仍需重新检查这个门槛，不能信任模型自行遵守。

备选方案是先评分再发起独立压缩请求。它会增加一次输入/输出成本和失败路径，也使“评分与压缩独立”变成两个请求间的编排；本方案选择一次请求，在 prompt 中隔离任务边界。

### 2. 完整正文参与评分，按字符预算分批

删除评分构造器和批次估算器中的固定 `[:2000]`。两者共用同一个序列化 helper，确保估算字段、JSON 转义和实际发送内容完全一致。普通条目按 `llm.max_prompt_chars` 进行批次装箱，保留全局 id，模型返回的 id 必须是该批次输入中的唯一整数。

单条正文超过批次预算时不得静默截断：该条目单独成批并打印超预算告警；配置文档将 `max_prompt_chars` 说明为批次目标上限，部署者必须把它设在所用模型上下文窗口以内。若供应商拒绝该请求，沿用评分失败回退，不伪造压缩正文。后续若真实数据出现大量超大文章，再另立分块/map-reduce 变更。

备选方案是把超大正文截回旧的 2,000 字符。该方案会重新引入本次要消除的信息丢失，因此拒绝。

### 3. 用可配置字符阈值决定是否请求压缩

在 `llm` 配置中增加 `content_compaction_threshold`，单位为 Unicode 字符，初始建议值为 2,000；只有 `len(content) > threshold` 才在响应中要求模型生成正文。等于阈值时不压缩。字符阈值与日志的字数统计保持一致，避免 token/字符两个口径混淆；完整 prompt 的安全边界仍由 `max_prompt_chars` 负责。

`lowest_retained_score` 由调用层计算为 `min(filter.min_score, filter.hot_threshold)`，作为显式 prompt 变量传入。低于该分数的 item 仍返回分类、评分、标签和摘要，以维持现有归档和筛选流程，但不得返回模型生成的 `content`；合并程序保留原始正文。

### 4. 同名 content 覆盖，采用严格的 fail-open 合并规则

合并评分结果时按全局 `id` 找回原条目：

1. 先合并 `domain`、`score`、`tags`、`summary`。
2. 仅当模型 `content` 是字符串、非空、原文也是可比较字符串，且 `len(new_content) < len(original_content)` 时才覆盖原 `content`。
3. 缺失、空值、非字符串、等长、更长、重复 id、越界 id 或解析失败时，保留原文；不得因压缩失败丢弃条目。
4. 分数低于 `lowest_retained_score` 时，即使模型违规返回 `content`，程序也忽略该返回并保留原文。

不增加 `compressed_content` 或状态字段。这样 `_get_push_prompt_entries`、digest、即时推送和历史文件格式继续只处理 `content`。

### 5. 压缩提示词优先保真而非固定比例

压缩指令要求尽量沿用原文措辞和事件顺序，保留所有影响理解或核验的主体、时间、数字、金额、比例、版本、来源口径、因果关系、条件和不确定性；只删除广告、导航、图片语法、重复段落和无实质信息的修辞。不得添加原文没有的事实、数字、归因、推断或投资判断。

阈值只决定“是否尝试压缩”，不是强制输出长度。模型若无法在较短篇幅内安全保留关键信息，可以返回原文或不返回 `content`，程序将回退；程序不以激进截断换取目标比例。

### 6. 日志只记录实际采用的变短内容

由 `score_batch()` 在最终结果合并时记录日志；它只会处理模型按 prompt 契约返回的已配置领域条目。对每个被采用的更短 `content` 打印：`link`、原文字数、新文字数和

`(原文字数 - 新文字数) / 原文字数 * 100`。

百分比使用字符数并保留一位小数；原文为空时不覆盖、不计算、不打印。没有返回正文或正文没有严格变短的条目不打印压缩日志。日志属于运行观测，不写入 fetch JSON 或推送内容。

### 7. 保护正文去重能力

压缩后的 `content` 会成为持久化字段，而现有精确/模糊去重会读取它；这可能使同文转载在跨日比较时失去匹配。为保持精确正文去重，只有有效压缩的持久化条目新增内部 `_source_content_hash`：对压缩前规范化原始正文计算稳定 SHA-256。新抓取条目在比较时即时计算同一指纹；历史或未压缩条目没有该字段时从其持久化正文计算指纹，并继续保留现有 link/title/content 回退规则。

`_source_content_hash` 只用于存储层去重，必须由评分、digest 和即时推送的 prompt 字段白名单排除；为此，下游输入改为按 prompt 已声明的字段显式构造，而非复制整个 entry。它不是正文替代字段，也不改变下游 `content` 契约。压缩后的正文仍可能改变 RapidFuzz 的近似相似度，这是需要测试覆盖的已知权衡。

## Risks / Trade-offs

- **完整正文使评分输入变大** → 仍按完整内容分批；用一次调用同时产出压缩正文，只有后续重复使用产生节省时才有净收益；记录前后字符/token 规模供实际账单校准。
- **高保真压缩遗漏数字或限定条件** → prompt 明确保真清单；程序只做类型和长度安全校验；用 AI、Investment 真实长文做人工/规则回归，失败则保留原文。
- **模型违反低分输出门槛** → 合并层再次按 `lowest_retained_score` 丢弃模型 `content`，不能只依赖提示词。
- **单条正文超过上下文窗口** → 不截断，单独成批并告警；请求失败时沿用评分失败路径；分块压缩留作后续范围。
- **压缩正文改变正文去重结果** → 使用排除在 prompt 之外的原文指纹；旧文件无指纹时兼容旧算法，并覆盖精确与近似去重回归。
- **模型返回 id 错配或重复** → 校验 id 必须为当前输入的唯一整数；无效结果只回退对应条目，不把一个条目的正文写入另一个条目。
- **日志噪声增加** → 只在实际采用且严格变短时逐条打印，并统一包含 link 与百分比，便于检索。

## Migration Plan

1. 同一提交中更新 `config.yaml`、配置模型、评分 prompt、评分/合并逻辑、原文指纹去重兼容逻辑和测试；为新阈值提供明确的初始配置值。
2. 更新 README 与 `docs/tech-spec.md`，说明完整正文评分、最低分门槛、同名 `content` 覆盖、日志格式和超大单条策略。
3. 先将压缩阈值设置为高于现有数据最大正文长度进行灰度验证；确认日志和质量后启用默认阈值。
4. 回滚时将阈值调高即可：评分仍可继续使用完整正文，合并层因没有候选压缩正文而保留原文。若需要恢复旧评分输入，需单独回滚代码版本，不依赖历史数据迁移。
