## Why

评分阶段目前只把正文前 2,000 个字符交给模型，文章尾部的关键事实可能因此丢失；评分后的完整正文又会被 digest 和即时推送重复携带，造成后续上下文 token 浪费。让同一次评分调用在读取完整正文的同时产出高保真压缩正文，可以在不引入额外 LLM 调用的前提下减少后续输入规模。

## What Changes

- 评分 prompt 不再固定截断正文前 2,000 个字符，而是在安全的批次预算内传入完整 `content`。
- 在同一评分响应中明确分离分类、评分和内容压缩任务；压缩只依据原始标题与正文，尽量保留原文的关键信息、顺序、数字、来源和限定条件。
- 将 `min_score` 与 `hot_threshold` 的较小值作为最低压缩分数传入 prompt；低于该分数的条目不执行压缩且不输出评分响应中的 `content` 字段，但其分类、评分和摘要结果仍保持现有流程可用。
- 压缩结果继续使用现有的 `content` 字段，不新增 `compressed_content` 或状态字段；合并时仅接受比原文更短且有效的结果，否则保留原文。
- 评分完成后，对实际变短的条目打印其链接、原文字数、压缩后字数和相对原文的节省百分比。
- 超过阈值的条目可能以高保真改写后的 `content` 持久化；低于阈值的条目继续保留原始 `content`，不改变下游字段和处理流程。
- 为避免正文被覆盖后削弱跨日精确去重，可增加不可读的原文指纹元数据；该元数据不参与任何 digest 或推送 prompt。

### New Capabilities

- `score-content-compaction`: 在评分阶段基于完整正文完成独立分类、评分和高保真内容压缩，并为有效压缩提供可观测的节省日志。

## Impact

- `src/llm.py`：评分 prompt 构造、批次字符预算、评分结果解析与合并、压缩节省日志。
- `src/config.py` / `config.yaml`：新增或调整正文压缩阈值及 prompt 相关配置，并向评分 prompt 注入最低保留分数。
- `prompts/score/score_batch.md`：拆分独立任务、定义最低分数门槛和高保真 `content` 输出契约。
- `src/main.py` 及存储数据：继续消费同名 `content` 字段，但保存内容可能已被高保真压缩；低分条目保留原始正文。
- `src/storage.py`：若采用原文指纹，扩展去重读取和比较逻辑，并兼容没有该字段的历史文件。
- `tests/`：增加完整正文传入、压缩覆盖/回退、低分门槛、日志百分比及下游字段兼容测试。
