## Purpose

在预定档位模型运行中不可用时，用同一个接口上的可选备用模型再试一次，让评分、快讯、汇总不必整条停掉。备用名不是另一档，也不改启动时对三档主模型的探测。

## ADDED Requirements

### Requirement: 可选的同接口兜底模型

系统 SHALL 允许在 LLM 配置中声明一个可选的兜底模型名。该项 MUST 与三档主模型共用同一组接口参数（服务地址、API Key 环境变量名），系统 SHALL NOT 允许兜底模型使用不同的接口地址或凭据。

未声明该项时，系统 MUST 按现有行为完成配置加载与调用。声明该项时，模型名 MUST 为非空且去除首尾空白后仍有内容；空白值 MUST 视为配置无效。

兜底模型名 MUST 独立于三档映射：系统 SHALL NOT 要求把它写进档位字典，也 SHALL NOT 把它当成第四档。

#### Scenario: 未声明兜底时配置仍合法

- **WHEN** 配置只声明了三档主模型、未声明兜底模型名
- **THEN** 系统正常完成配置加载，运行行为与未引入兜底时一致

#### Scenario: 声明非空兜底名时配置通过

- **WHEN** 配置在三档之外声明了一个非空兜底模型名
- **THEN** 系统正常完成配置加载

#### Scenario: 空白兜底名被拒绝

- **WHEN** 配置声明了兜底模型名，但其值为空字符串或仅含空白
- **THEN** 系统在启动阶段报告配置校验失败，进程退出

### Requirement: 运行中主模型耗尽后再打一枪

系统发起一次允许兜底的 LLM 调用时，MUST 先使用该次调用指定档位的主模型，并按既有重试策略在该主模型上重试。主模型请求成功时，系统 SHALL NOT 再请求兜底模型。

仅当该档主模型在既有重试策略结束后仍失败，且已声明可用的兜底模型名、并且该名称与当前档位主模型名不同时，系统 SHALL 改用兜底模型再发起恰好一次请求。这一次兜底请求 SHALL NOT 再套用主模型的重试次数。

兜底请求成功时，系统 MUST 将该次调用视为成功，并留下可观察的日志，指明从哪一档主模型切到了兜底模型。系统 SHALL NOT 因此次成功切换发送异常通知。

兜底请求失败时，系统 MUST 将该次调用视为失败，失败表现与未配置兜底时主模型最终失败一致。

下一次调用 MUST 再次先打该档主模型。系统 SHALL NOT 在进程内记住「主模型已挂」而跳过主模型。

#### Scenario: 主模型成功则不切兜底

- **WHEN** 一次允许兜底的调用中，指定档位的主模型在既有重试策略内返回成功
- **THEN** 该次调用成功返回，请求中未出现兜底模型名

#### Scenario: 主模型耗尽后兜底一次成功

- **WHEN** 一次允许兜底的调用中，指定档位的主模型按既有重试策略结束后仍失败，且已声明与该档主模型不同的兜底模型名
- **THEN** 系统用兜底模型再请求恰好一次；该次成功后调用成功返回，并留下指明档位与两个模型名的日志

#### Scenario: 兜底一次失败则本次调用失败

- **WHEN** 主模型已失败且系统已对兜底模型发起那一次请求，该次请求也失败
- **THEN** 系统报告该次调用失败，SHALL NOT 再对兜底模型重试

#### Scenario: 未声明或同名时不切

- **WHEN** 主模型按既有重试策略结束后仍失败，且未声明兜底模型名，或声明的名称与当前档位主模型名相同
- **THEN** 系统报告该次调用失败，SHALL NOT 再发起另一次请求

#### Scenario: 下一次调用仍先打主模型

- **WHEN** 前一次调用已通过兜底模型成功返回，系统再次发起同档位调用
- **THEN** 本次请求首先携带的仍是该档主模型名

#### Scenario: 不可重试的主模型失败也会切兜底

- **WHEN** 一次允许兜底的调用中，主模型返回不可按既有策略重试的失败（例如模型不存在），且已声明不同的兜底模型名
- **THEN** 系统不再对主模型重试，改用兜底模型再请求恰好一次

### Requirement: 兜底不跨档也不换供应商

系统 SHALL NOT 在主模型失败后改用其他档位的主模型完成该次调用。兜底 MUST 只替换请求中的模型名，MUST 继续使用同一服务地址与同一 API Key。

业务调用点 MUST 仍只声明档位，SHALL NOT 为了启用兜底而改写评分、即时快讯或定时汇总的调用方式。

#### Scenario: 中档失败不会改打低档

- **WHEN** 一次使用 `medium` 档的调用在主模型失败后进入兜底
- **THEN** 兜底请求携带的是配置中的兜底模型名，SHALL NOT 携带 `low` 档的主模型名

#### Scenario: 兜底请求仍走同一接口

- **WHEN** 系统对兜底模型发起那一次请求
- **THEN** 请求使用的服务地址与 API Key 与该次主模型请求相同

### Requirement: 启动探测不走兜底

系统在启动阶段探测各档可用性时，MUST 只使用该档主模型，SHALL NOT 在探测失败后改用兜底模型把该档标为可用。

任一档主模型探测失败或超时时，系统 MUST 中断启动并报告该档失败，即使兜底模型名已声明且可用。

评分、即时快讯与定时汇总的运行期调用 MUST 默认允许兜底，无需调用方额外声明。

#### Scenario: 某档主模型探测失败即使兜底可用也中断启动

- **WHEN** 启动探测中某一档主模型失败或超时，且配置中已声明可用的兜底模型名
- **THEN** 启动流程中断，错误信息包含该档位名，探测过程中未使用兜底模型名

#### Scenario: 运行期业务调用默认允许兜底

- **WHEN** 系统在运行中为评分、即时快讯或定时汇总发起 LLM 调用，且主模型按既有策略失败、兜底名可用且不同
- **THEN** 系统对该次调用使用兜底模型再请求恰好一次
